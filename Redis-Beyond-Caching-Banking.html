Instant payments processingFlagship demo▸
Business problem

Reference architecture
Payment events → Streams (XADD)→Consumer groups process in order, at-least-once→Idempotency key (SET NX) prevents double-post→Atomic balance update + ledger event→Active-Active for always-on across regions
Impact
100k+
Payments/sec
exactly once
Posting semantics
<5 ms
Per-event latency
Live demo flow

  2. Consumer group posts each exactly once with idempotency keys.
  3. Replay a duplicate and show it's safely ignored.
  4. Show throughput and per-event latency live.
Value by stakeholder
Solution Architect
Event-driven payments without standing up Kafka.
Platform & SRE
Consumer groups + Active-Active = resilient, always-on.
Developer
Idempotency and ordering with primitives, not frameworks.
Sample
# idempotent debit + ledger
SET pay:{txnId} PENDING NX EX 60        # claim once
INCRBYFLOAT acct:{id}:bal -9500
XADD ledger * txnId {txnId} acct {id} amt -9500 status POSTED
XACK payments grp {msgId}
